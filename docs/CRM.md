# Bakhtech CRM

The admin CRM is a Laravel and React implementation informed by the user-supplied FluentCRM archives and the locally installed WordPress plugins at `bakhtech.local`. The installed FluentCRM and FluentCampaign Pro controllers, including `RecurringCampaignController` and `SequenceController`, were inspected as workflow references. The WordPress plugins are not installed or loaded by this Laravel app because they depend on WordPress hooks, authentication, tables, and runtime. Embedding the WordPress admin would also require a separate authenticated session and would not use this app's CRM data. A native implementation preserves the existing access controls and data model.

## Available workflows

- Contacts are linked by email to contact messages, quote-builder requests, bookings, and invoice clients. Source records appear in the contact activity timeline. Quote-builder requests create deals.
- Contacts have stages, service interest, notes, follow-up tasks, email subscription status, lists, and tags.
- The CRM Forms section shows the site's contact, quote, and booking forms with real entry and CRM-contact counts. It opens the public form and filters contacts whose histories include that form source.
- CRM Settings configures the app's actual SMTP sender, sends a test message, and shows delivery logs. CRM Reports has contact growth, email delivery/activity, and business reporting tabs.
- The CRM is embedded in the Bakhtech admin dashboard. Clicking CRM expands the existing sidebar menu; its Dashboard, Contacts, Emails, Forms, Automations, Reports, Settings, and business tools open in the same admin content area.
- Automation workflows support up to 20 ordered actions: add/remove a list or tag, create a task, add a note, or enroll in an active email sequence. Actions run atomically once per contact event; failed runs roll back their action changes.
- The Contacts navigation contains All Contacts, Lists, Tags, and Segments. Segments are saved filters for stage, subscription, source, list/tag, and text search; their contact counts update as records change.
- Companies, deals, and projects are managed separately. Contact profiles show related deals, projects, quotes, invoices, and balances.
- CSV import accepts `name,email,phone,company,source`; export downloads contacts. Imported contacts start unsubscribed.
- Email campaigns start with an internal title and editor choice, then open setup for subject, audience, and body. The three creation choices have separate interfaces: Default Editor builds ordered content blocks, Raw HTML has a source editor and isolated live preview, and Visual Builder arranges styled sections with a settings panel. Drafts can be scoped to a list or tag, prepared for subscribed contacts, and sent in batches from the configured Laravel mail transport. Each delivery is recorded, and every message contains a signed unsubscribe URL. `{{name}}` and `{{email}}` are supported in the subject and body. These three editors send HTML; older Classic drafts remain plain text.
- The campaign list includes title search, status filter, sortable columns, page size controls, pagination, draft setup, duplicate, and delete actions. Campaign setup opens in a separate drawer. Open and click rates are shown as unavailable because plain-text campaigns do not track those events.
- The Emails navigation includes Campaigns, Recurring Campaigns, Sequences, Templates, Patterns, and All Activities. Templates and Patterns are saved in the database and can create campaign drafts. All Activities shows campaign delivery records.
- Recurring Campaigns can send daily, weekly, or monthly to the subscribed audience. Each occurrence creates a campaign and delivery history. Email Sequences contain ordered steps with day delays. Contacts enroll when subscribed or added to the chosen list/tag; admins can also enroll the current audience. Both workflows can be paused, edited, and monitored. Failed runs can be retried. Sending uses the existing campaign sender and unsubscribe links.
- Automations have a full-page workflow builder, starter workflows, searchable/filterable listing, active/paused controls, duplication, deletion, and execution metrics. Triggers cover contact creation, stage changes, subscription changes, and list/tag membership additions. Entry filters combine stage, source, subscription status, and membership. Test previews use current contact data and roll back every change without sending email or saving run records. History supports search, status/date filters, step outcomes, and retries using the original action snapshot. Activation applies to future matching events. Automation actions do not recursively trigger other workflows. Sequence enrollment respects subscription consent and the sequence audience; delivery follows the existing scheduler.
- CRM reports show lead sources, conversion, deal values, project counts, outstanding invoices and quotes, and received revenue.

## Operations

### Predesigned email templates

Use **Browse templates** inside Content blocks or Visual builder to choose from ten designs: welcome, product launch, newsletter, promotion, event invitation, service proposal, appointment, onboarding, feedback, and re-engagement. Both editors support the complete collection. Custom HTML includes one responsive, table-based Studio Letter layout with marked editing areas.

Before applying a template, enter the brand name, upload a logo or paste its public image URL, and add the website, email, phone, and address. Empty contact fields are omitted. Each block-based design includes dedicated Logo and Contact info blocks, which can also be added from the palette. Logo width, text, colors, spacing, and contact details remain editable after saving and reopening. Applying a design asks before replacing existing content; block-editor Undo can restore it. Replace bracketed sample copy and set the campaign's button destination before sending. Browser previews do not guarantee identical rendering in every mail client.

Run `php artisan migrate --force` after deployment and configure the existing application mail settings before sending campaigns. Sending a campaign requires two explicit admin steps: prepare its audience, then send. Only contacts marked subscribed are included. Recurring campaigns and sequences require the Laravel scheduler to run every minute (`php artisan schedule:run` from cron); `php artisan crm:run-email-programs` runs due work manually. Scheduled sends process up to 100 recipients per run and resume on the next tick. The local frontend is available with `npm.cmd run dev` in `frontend/` and the API with `php artisan serve --host=127.0.0.1 --port=8000`.

## Scope

The WordPress-specific and premium plugin integrations are not present: WordPress users, WooCommerce, LMS tools, FluentForms, third-party SMS, the Gutenberg builder, behavioral click/open tracking, and advanced branching funnels. FluentCRM's Forms page in the installed plugin reads Fluent Forms data through WordPress. The Bakhtech Forms section instead reads this application's real intake forms; it does not include the separate Fluent Forms builder. The three email editors are native Bakhtech tools and do not run the WordPress plugin builders. Recurring and sequence scheduling follows the installed plugin's core pattern of a stored workflow, scheduled runs, and delivery records, but does not reproduce all premium scheduling rules and funnel actions. This CRM uses the Bakhtech app's own customer records and mail transport.
